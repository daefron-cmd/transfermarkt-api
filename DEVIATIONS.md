# Deviations from stock pawl

adopted-from: c84d834
last-synced: never

One row per deliberate departure from stock pawl, written when the decision was made. Tags and the
convergent/divergent distinction are defined in [CLAUDE.md](CLAUDE.md).

| date | surface | deviation | why | stock behaviour replaced | removal condition |
|---|---|---|---|---|---|
| 2026-09-26 | Stop hook | [waiver] Stop hook declined: `[tool.mech] stop_hook = false`, and both `.codex/hooks.json` (the file `mech.validation` reads at c84d834) and `.claude/settings.json` are `{ "hooks": {} }`. | The maintainer's decision. The hook blocks nothing that the fail-closed commit gate does not already block. Cost is not the reason: the offline suite measured 1.9 s serial (`uv run pytest -q`, 403 tests) and the whole commit gate 4.6 s, so per-turn cost would be small. Divergent. | A registered Stop hook that runs the full suite in a fresh random order after every agent turn, report-only. | Register the hook (and delete `stop_hook = false`) if sessions start running many turns between commits and failures noticed only at commit time cost real rework. |
| 2026-09-26 | ruff | [pin] `[tool.ruff] line-length = 120`. | This repo's house width since before adoption; the product code is formatted at 120. Divergent. | ruff's default width of 88. | When this repo reformats its product code to 88. |
| 2026-09-26 | interpreter | [pin] `.python-version` stays `3.13` (not `3.13.15`); this deployment, including Pawl's suite (`mech.selftest`), is verified on CPython 3.13.13, the interpreter uv resolves locally. CI and Docker resolve their own 3.13.x. | Adoption does not move the target's interpreter. `requires-python` stays `>=3.12` for the product; `mech/` itself only ever runs on 3.13 here (dev, CI). Divergent. | `.python-version` pinned to exactly `3.13.15`. | When this repo pins `.python-version` to `3.13.15` or later as its own change. |
| 2026-09-26 | pyright | [pin] `pyrightconfig.json` `"pythonVersion": "3.12"`. (`[tool.ruff] target-version = "py312"` is not a deviation: stock guidance sets it to the target's Python.) | `requires-python = ">=3.12"`, so pyright must flag 3.13-only syntax and stdlib use in product code. Divergent. | `"pythonVersion": "3.13"`. | When `requires-python` moves to `>=3.13`; then set `3.13`. |
| 2026-09-26 | ruff | [port] `mech/` is held to Pawl's own rule set: `per-file-ignores` `"mech/**" = ["B", "C4", "SIM", "RUF", "FAST"]` and `[tool.ruff.format] exclude = ["mech/**"]`. The commit gate's `ruff format --check` therefore does not check `mech/`. | This repo selects more rules than pawl (B, C4, SIM, RUF, FAST) and formats at 120. Measured at adoption: under the host config, `ruff check --fix` and `ruff format` would have rewritten 25 verbatim `mech/` files (70 RUF100, 1 B007, RUF005, RUF059, RUF001, plus reformatting at 120), forking upstream bytes. `mech/` passes `ruff check` and `ruff format --check` under pawl's own `pyproject.toml`. Convergent. | `mech/` linted and formatted by the host repo's ruff config like any other code. | When this repo's ruff config matches pawl's for `mech/` (width 88, no extra rules), or when pawl ships an equivalent (e.g. `mech/` carrying its own scoped ruff config). At each sync, check `mech/` with pawl's config, since the local gate no longer formats it. |
| 2026-09-26 | registration | [port] `.claude/settings.json` (`{ "hooks": {} }`) is kept alongside stock `.codex/hooks.json`. | The Claude Code adoption skill prescribes `.claude/settings.json`, but at c84d834 `mech.validation` and the self-test digest read `.codex/hooks.json` and nothing in `mech/` reads `.claude/settings.json`. Both register nothing, so Claude Code and Codex agree that no hook is registered. Convergent. | Only `.codex/hooks.json`. | Delete whichever file `mech.validation` does not read once pawl's Claude Code packaging settles it, or when pawl ships an equivalent. |
| 2026-09-26 | commit gate, push CI | [scope] The gate's and push CI's pytest inherit this repo's `addopts` (`--disable-socket --allow-unix-socket -m "not live"`), so `tests/live` (25 tests at adoption) is never run by either. | The live suite hits transfermarkt.com and tmapi over the network; the gate must stay offline and deterministic. The nightly `live.yml` runs the `tmapi` subset; the rest is a local run. Divergent. | pawl sets no `addopts`, and the gate runs the whole product suite. | None while the live suite needs the network: a decision to live with this. Revisit if live cases gain recorded fixtures. |
| 2026-09-26 | push CI mutation scope | [scope] `[tool.mutmut] only_mutate` in `pyproject.toml` is the current ratchet (it lists the burned-down modules; `pyproject.toml` is the record, not this row): push CI mutation-tests only the listed modules, and its coverage-reachability check narrows to the same inventory (`mech.source_inventory` honours `only_mutate`), so unlisted `app/` modules are neither mutated nor checked for coverage reachability in push CI. The list is a burndown ratchet, extended in the same commit that burns a module down. | `mech/ci_push.py` treats any push touching `pyproject.toml` or `uv.lock` as a full-mutation input (`FULL_MUTATION_INPUTS`) and then mutates every module in `source_paths`. On this 64-module brownfield repo, at adoption with a baseline classified for one module (`app.http`), that was about 5,640 mutants and 19 min per such push (supervisor estimate), red on unclassified survivors. Narrowing through stock config makes the trigger's scope match the baseline without forking `mech/`. Divergent. | Push CI mutates, and checks coverage reachability for, every module under `source_paths` (all of `app/`). | Delete `only_mutate` when every `app/` module has been burned down and its survivors classified in `MUTANTS.md`. |
